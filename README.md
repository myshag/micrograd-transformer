# Минимальный autograd

Учебный движок автоматического дифференцирования (~150 строк), по мотивам
[micrograd](https://github.com/karpathy/micrograd). Считает градиенты через
обратное распространение (backpropagation) — основу обучения нейросетей.

## Файлы

**Часть 1 — скалярный движок (теория):**
- `autograd.py` — движок на одиночных числах (класс `Value`)
- `demo.py` — примеры: проверка градиентов, нейрон, градиентный спуск

**Часть 2 — тензорный движок + MNIST (практика):**
- `tensor.py` — тот же autograd, но узлы графа — матрицы numpy (класс `Tensor`)
- `download_mnist.py` — скачивает датасет в `data/mnist.npz`
- `mnist.py` — MLP `784→128→10`, обучается до **~97%** за 5 эпох

**Часть 3 — API, базово совместимый с PyTorch:**
- `nn.py` — `Module`, `Linear`, `ReLU`/`Tanh`/`Sigmoid`, `Sequential`, `CrossEntropyLoss`
- `optim.py` — оптимизаторы: `SGD` (с моментом) и `Adam`
- `api_demo.py` — тот же код, что и на PyTorch (кастомный `Module`, `state_dict`, …)

**Часть 4 — свёрточная сеть (CNN):**
- `tensor.py` — операции `conv2d`, `maxpool2d`, `reshape` (через im2col)
- `nn.py` — `Conv2d`, `MaxPool2d`, `Flatten`
- `mnist_conv.py` — CNN, **~97–99%** на MNIST
- режим `no_grad` (как `torch.no_grad()`) — инференс без построения графа

**Часть 5 — трансформер с нуля:**
- `tensor.py` — `softmax`, батчевый `matmul`, `swapaxes`/`mT`, `__pow__`, эмбеддинги
- `nn.py` — `Embedding`, `LayerNorm`, `MultiheadAttention`,
  `TransformerEncoderLayer`, `TransformerEncoder` (+ каузальный маск)
- `primes.py` — мини-GPT, который **генерирует простые числа**
- 📘 **`docs/transformer-from-scratch.md`** — учебник: трансформер с нуля

## Как это работает

### 1. Граф вычислений
Каждое число оборачивается в объект `Value`. Когда мы пишем `c = a * b`,
движок не только считает `a.data * b.data`, но и запоминает, что `c`
получился **из** `a` и `b` через операцию `*`. Так выражение превращается
в граф: листья — входные числа, корень — итоговый результат (обычно loss).

```
a ──┐
    (*)── (a*b) ──┐
b ──┘             (+)── f
c ────────────────┘
```

### 2. Forward (прямой проход)
Просто вычисляем значения снизу вверх по графу — это обычная арифметика.
Параллельно для каждого узла сохраняется его «локальная производная»
в виде замыкания `_backward`.

### 3. Backward (обратный проход) и chain rule
Цель — найти производную итога (`f`) по каждому входу. Опирается на
**цепное правило**: если `f` зависит от `u`, а `u` от `x`, то

```
df/dx = df/du · du/dx
```

Алгоритм:
1. **Топологическая сортировка** графа — упорядочиваем узлы так, чтобы
   каждый шёл после своих родителей.
2. Ставим `f.grad = 1` (производная f по самой себе).
3. Идём от корня к листьям. На каждом узле его `_backward` берёт
   накопленный `out.grad` и **умножает на локальную производную**, передавая
   результат родителям.

Локальные производные для каждой операции:

| операция      | результат | производная по входам                 |
|---------------|-----------|---------------------------------------|
| `a + b`       | сложение  | `1` и `1` (градиент проходит как есть) |
| `a * b`       | умножение | `b` и `a`                             |
| `a ** n`      | степень   | `n · a^(n-1)`                         |
| `tanh(x)`     | нелинейн. | `1 - tanh(x)²`                        |
| `relu(x)`     | нелинейн. | `0` при `x<0`, иначе `1`              |

### 4. Почему `+=`, а не `=`
Один узел может использоваться в нескольких местах графа (например `x` входит
и в `x*w` и в отдельное слагаемое). По правилу для функций многих переменных
вклады по всем путям **складываются**. Поэтому градиент накапливается через
`+=`. Из-за этого перед каждым новым backward градиенты нужно обнулять
(`x.grad = 0.0`) — иначе они «протекут» из прошлой итерации.

### 5. Обучение = градиентный спуск
Имея `loss.backward()`, мы знаем, как каждый параметр влияет на loss.
Двигаем параметры в сторону, **противоположную** градиенту:

```python
loss.backward()
param.data -= learning_rate * param.grad
```

Повторяем — loss падает. Это и есть обучение. Пример 3 в `demo.py`
показывает это на функции `(x-3)²`: `x` сходится к 3.

## Часть 2: от скаляра к тензорам и MNIST

Скалярный `Value` нагляден, но обучать на нём MNIST нереально: одна картинка —
784 входа, в датасете 60 000 картинок, и каждое число стало бы отдельным
Python-объектом → миллионы объектов на один проход. Решение — узел графа,
который хранит **целый массив** numpy. Математика backprop та же, меняются
только операции.

### Что нового в `tensor.py`

**Матричное умножение** — основа линейного слоя `X @ W`. Его производные:
```
C = A @ B   →   dA = dC @ Bᵀ ,   dB = Aᵀ @ dC
```

**Broadcasting.** numpy умеет складывать массивы разной формы, «растягивая»
меньший (например, вектор-смещение `b` формы `(10,)` прибавляется к матрице
`(N, 10)`). При backward градиент нужно «сжать» обратно, просуммировав по
растянутым осям — это делает `_unbroadcast`. Это главная новая тонкость
по сравнению со скаляром.

**Softmax + кросс-энтропия одним блоком.** Для классификации на 10 цифр выход
сети превращают в вероятности (softmax) и сравнивают с правильным ответом
(кросс-энтропия). По отдельности они численно неустойчивы, а вместе дают
простой и стабильный градиент:
```
∂loss/∂логиты = (p − y_onehot) / N
```
где `p` — предсказанные вероятности, `y_onehot` — правильный ответ, `N` — размер батча.

### Сеть в `mnist.py`
```
вход 784 ──(W1,b1)──► 128 ──ReLU──► ──(W2,b2)──► 10 логитов ──► softmax+CE
```
- **Инициализация He** (`√(2/n_in)`): правильный масштаб весов, иначе сигнал
  по слоям либо взрывается, либо затухает.
- **Цикл обучения** на каждом батче: forward → обнулить градиенты →
  `loss.backward()` → шаг SGD `p.data -= lr * p.grad`.

### Результат
```
эпоха 1: loss = 0.37, точность = 0.937
...
эпоха 5: loss = 0.10, точность = 0.970
```
~97% точности на тесте, обучено с нуля на собственном autograd, без PyTorch.

## Часть 3: API, базово совместимый с PyTorch

Цель — чтобы код модели выглядел **как настоящий PyTorch**, и обычный
туториал по torch переносился почти дословно. Совпадают:

| что | как в PyTorch и у нас |
|-----|----------------------|
| слой | `nn.Linear(in, out)`, атрибуты `weight`, `bias` |
| форма весов | `(out_features, in_features)`, forward `x @ weight.T + bias` |
| контейнер | `nn.Sequential(...)`, либо подкласс `nn.Module` с `forward` |
| функция потерь | `criterion = nn.CrossEntropyLoss(); loss = criterion(logits, y)` |
| оптимизатор | `optim.SGD(model.parameters(), lr, momentum)` / `optim.Adam(...)` |
| цикл шага | `zero_grad()` → `loss.backward()` → `step()` |
| веса | `model.state_dict()` / `load_state_dict()`, `named_parameters()` |

Один и тот же код запускается на нашем движке и на настоящем torch —
отличаются только строки `import` (см. шапку `api_demo.py`):

```python
class Net(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(784, 128)
        self.act = nn.ReLU()
        self.fc2 = nn.Linear(128, 10)
    def forward(self, x):
        return self.fc2(self.act(self.fc1(x)))

model = Net()
criterion = nn.CrossEntropyLoss()
optimizer = optim.Adam(model.parameters(), lr=1e-3)

logits = model(x)
loss = criterion(logits, y)
optimizer.zero_grad(); loss.backward(); optimizer.step()
```

Под капотом вместо `torch.Tensor` работает наш `Tensor`, а градиенты считает
наш autograd. Корректность операций (`matmul`, `transpose`, `sum`, `mean`,
`tanh`, `sigmoid`) подтверждена численной проверкой градиента (расхождение ~1e-10).

## Часть 4: свёрточная сеть и режим no_grad

**Свёртка через im2col.** Наивная свёртка — это вложенные циклы по окнам.
Трюк `im2col` разворачивает все окна изображения в столбцы одной матрицы,
и тогда свёртка = одно матричное умножение (его BLAS считает очень быстро).
Обратная операция `col2im` нужна в backward. На этом построены `conv2d`,
`maxpool2d`, `reshape` в `tensor.py` и слои `nn.Conv2d/MaxPool2d/Flatten`.
Градиенты сверены с численными (расхождение ~1e-9).

**Режим `no_grad`** (как `torch.no_grad()`). Каждая операция строит граф для
backward: узел хранит ссылки на родителей, замыкание `_backward` и массив
`grad`. При обучении это нужно, но при инференсе — лишняя память: за один
проход в RAM живут все промежуточные карты батча. Это приводило к пику
**3.2 ГБ** на оценке точности и падению по OOM.

Под `with no_grad():` граф не строится (`_prev` пуст, `_backward` не
регистрируется, `grad` не выделяется). Промежуточные тензоры сразу
освобождаются сборщиком мусора — в памяти только «фронт» вычисления.
Результат: тот же инференс при пике **744 МБ** вместо 3.2 ГБ.
